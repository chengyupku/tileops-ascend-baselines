`batch.py` groups adjacent native deployment modes into separate foreground processes, avoiding collisions between packages with the same Python/OPP name. `group.py` reuses imports within each deployment. Existing receipts are skipped. Each reservation releases after its bounded batch; rerun a queue to continue incomplete cases. Do not change modules already imported by a running group. Each numerical receipt archives the exact source hashes used for that check.

For continuation, `continuation.py` executes one homogeneous mode per reservation and stops at a complete-case boundary after 60 seconds, subject to the guard's 300-second hard deadline. Submit at most one live or pending guard for this owner; keep every remaining case in the CPU todo until the previous guard is terminal. Each new execution needs a new tag and receipt. A 75 is an unstarted reservation, not a numerical failure. Synchronization faults terminate the current batch immediately. Historical `batch.py`/`continue_checks.py` are retained for evidence; the continuation coordinator is `.cache/all-pairs/fla_continuation/sweep.py`.

`continue_checks.py QUEUE` is a CPU-only foreground coordinator that repeats finite guarded batches and refreshes coverage after each batch. It stops for inspection on any nonzero guard exit, failed checker process, device synchronization error, or lack of completed cases. Creating the own evidence file `stop_after_batch` stops it between reservations; it never releases or bypasses an active lock. Guard logs and receipts distinguish queue expiry, execution timeout and numerical failure.
