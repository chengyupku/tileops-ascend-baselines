# Independent ops-nn adapters

This directory is the isolated ops-nn implementation for the 205-operator manifest audit.
No shared registry, manifest, oracle, vendor source, or other task memory is modified.

`staging.CANDIDATES` holds source-reviewed implementations awaiting exact-case device acceptance.
`PROVIDERS` is the public, lazy entry point; final publication must be backed by the corresponding
full-output numerical and source-ownership receipts. Importing either entry point does not import
Torch, initialize the NPU, or compile a vendor module. All input-dependent transforms occur inside
`run`; only immutable source hashes are cached.

`pinned_smoke004/` is an exact byte-preserved deployment of the runtime used by 53 accepted
device cases. Public exact-case dispatch can use that version while the current staging version
awaits regression checks. `preserved_runtime.py` verifies every recorded dependency, complete
receipt, immutable native audit and relocated runtime hash before accepting it. Coverage marks
these rows `verified_preserved`, keeps staging status separately, and never counts relocation
as a new device run. This deployment requires the original tested `OPS_NN_VENDOR=install3/...`
environment; its older default vendor is deliberately left unchanged to preserve source bytes.

The independent package is generated by `build.py` from the original vendor JIT build. The only
reused deployment change is the previously reviewed MatMulV3 host dtype inference registration;
no native kernel math or schedule is edited. Install generations are separate (`install`, `install2`,
`install3`). Each graph call refuses an API absent from the selected own-vendor configuration.
Graph compilation, temporary files and caches are restricted to `.cache/all-pairs/ops_nn`.

Foreach inputs use `tensorlist.py`: the documented device pointer-list header is rebuilt
inside each call, with a full logical-size allocation required by GE validation. `hybrid.py`
is a retained rejected diagnostic route: its ACLNN wrapper selected system binaries and is
not used by providers. The accepted Graph route compiles and launches the isolated vendor.

Run device checks only with the host-wide reservation, including runtime imports:

```bash
npu-guard run --owner allpairs/ops_nn --wait 3600 --timeout 900 -- \
  env OPS_NN_VENDOR=/root/dyq/workspace/.cache/all-pairs/ops_nn/install3/vendors/allpairs_nn \
  bash TileOPs/benchmarks/ascend_all_pairs/ops_nn/run_batch.sh \
  --jobs /absolute/path/to/jobs.json --out /absolute/path/to/new-receipt-directory
```

900 seconds is for batches requiring native compilation; use 300 for cached short validations.
A jobs file contains `[{"op": "ReluFwdOp", "case_id": "hidden-state-decode-bfloat16"}]`.
`batch.py` calls the original shared checker unchanged, including independent CPU references,
complete manifest output checking, input preservation and existing special quantization checks.
`audit.py` additionally requires the selected ops-nn package's successful compiler source event,
the matching real stream kernel launch, and a matching Candidate source hash. A numerical pass
without that attribution is not accepted.
Continuous batch capture records delayed CANN log writes; case ownership uses the event's
own timestamp inside that exact case's interval. `recover_native.py` can recover original
compiler records from retained raw logs without inventing missing launches.
The successful original compiler event must also precede the matching native launch.
Per-case capture cursors advance incrementally and preserve partial lines across file
rotation; both per-case and continuous launch records require the exact receipt interval.
Graph descriptors and temporary buffers are released only after their recorded stream
event completes, so completed invocations do not accumulate until final cleanup.

Evidence is under
`.agent_memory/THREADS/tileops-progress-report-20261019/ALL_PAIRS/ops_nn`:

- `coverage.json`: explicit schema, all 205 operators and every frozen manifest case, source file,
  line/hash, adapter, numerical/attribution receipts and precise current status.
- `inventory_snapshot.json`: frozen input inventory; the parent inventory may continue to evolve.
- `source_index.json`, `semantic_decisions.json`: original API registration inventory and remaining
  semantic contract decisions; unsupported means no equivalent existing API within the permitted
  adaptation scope, not proof of impossibility under arbitrary algorithm reimplementation.
- `factory_audit.json`: missing benchmark registrations are separate from library support.
- `progress.json`: incremental progress; historical accepted rows are never counted as new runs.

Composed adapters name every original API they execute. Layout lifting, complete-axis packing,
zero padding/cropping, per-call broadcast, optional-parameter initialization, exact dtype widening
and declared output casts are explicit in Candidate.adaptation. No Torch arithmetic substitutes
for vendor normalization, convolution, reduction, activation or matrix multiplication.

`bitwise_bytes.py` and `ieee_lookup.py` use immutable input-independent truth tables with the
original `GatherV2` API. Byte interleaving creates exact bounded indices without computing the
requested predicates or bitwise outputs in Torch. Device table copies and every input-dependent
layout/mask are charged in `run`. FP32 classification combines original native 0/1 arithmetic;
replacement uses native `MaskedScatter`. `wide_truth.py` retains all FP64 magnitude bits while
preserving signed-zero semantics before original p=0 reduction. Their CPU bit-pattern checks
are representation evidence only, never a numerical device pass.

`logsumexp.py` recovers logsumexp from original LogSoftmax at the original maximum index,
using original GatherElements and subtraction. Native IEEE lookup masks, p=0 reductions and
MaskedScatter preserve NaN precedence and both infinite maxima. `extension_routes.py` records
this isolated addition without changing the shared catalog bytes used by earlier candidates.

`runtime_env.json` specifies the exact new and historical deployment environments. Select the
package before importing the device runtime. Historical providers retain their accepted classic
package and should run in a separate fresh process from new providers. `run_pending.py` offers
a foreground controller that reserves each batch independently, audits receipts, and publishes
only accepted cases; it stops on guard failure and defers failed operator families for review.
